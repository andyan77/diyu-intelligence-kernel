## 一、角色分配提案

| 角色 | 厂商/型号家族 | 理由 |
|---|---|---|
| **A/B 主模型**（笛语侧与基线侧同用） | Qwen 旗舰指令模型（qwen-max 当前代） | 中文商业文案与结构化输出能力强；两侧同模型满足 B.2.2"同条件" |
| **多模态**（商品图 VisualProfile） | qwen-vl-max 当前代 | OD-02 已裁决多模态用 Qwen 系；与主模型同厂减少集成面 |
| **trace_auditor / L2 探针** | DeepSeek（deepseek-chat 当前代；深审场景可用 deepseek-reasoner） | 跨厂商审计：系统侧 Qwen、审计侧 DeepSeek，两家物理分离，防同门自审 |

## 二、生成参数提案（IA-0 定格时写死并计算 generation_parameters_hash）

| 参数 | 提案值 | 说明 |
|---|---|---|
| temperature | 0.3 | 决策/结构化输出场景压随机性；创意阶段是否单独放宽 → IA-0 一并裁决 |
| top_p | 0.8 | 配合低温 |
| seed | 固定值（定格时指定） | 可复跑性 |
| max_tokens | 按阶段 D / C 分别定上限 | 防无限调用换质量（B.2.2） |
| 采样口径 | 日常 n=1；Gate 正式验收 n=3，任一次命中一票阻断标签即记（就严不就宽） | C.6 已裁决口径，照录 |

## 三、定格程序（IA-0 当日执行，防幻觉：版本串一律实测不手写）

1. 用 `.env` 密钥调两家 models API 列出**当日实际可用**型号与版本串（只读调用）；
2. 将实测版本串填入 14 份 Case Manifest 的 model_provider / model_name / model_version；
3. 参数表定稿 → 计算 generation_parameters_hash 填入；
4. 与 14 份 Manifest、两阶段基线 Prompt、匿名流程同包提交 Founder 签字（B.2.1 approved_by）。

> 本文件不出现具体版本号是刻意的：训练记忆里的型号串不可信，IA-0 以 API 实测为准（不假绿）。
