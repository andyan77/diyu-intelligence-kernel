# 笛语智能核 · CI 封闭化依赖锁（requirements-lock.txt；IA-1 送签前置收尾块，2026-08-18）
#
# 与 requirements.txt 的分工：
#   requirements.txt  = 人读人改的**直接依赖**清单（三个真实 import 的包 + 取证条件说明，仍是版本语义真源）；
#   本文件            = CI 安装用的**全量封闭锁**（直接 + 传递依赖，逐包钉版 + sha256 哈希），
#                       由 requirements.txt 在干净 venv 实测解析生成，**不得手编版本或哈希**。
# 再生成方法（改 requirements.txt 后必须同批重生成）：
#   python3 -m venv v && ./v/bin/pip install pip==25.2 && ./v/bin/pip install -r requirements.txt
#   && ./v/bin/pip freeze → 逐包 pip download → sha256sum 回填本文件 → 干净 venv
#   `pip install --require-hashes -r requirements-lock.txt` 实测 exit 0 + tools/check_m0.py 六步全绿。
#
# 生成环境（2026-08-18 实测）：Python 3.10.12（cp310，linux x86_64 glibc）+ pip 25.2；
#   哈希对应 PyPI 该版本的 py3 通用 wheel 或 cp310 manylinux wheel——与 CI（ubuntu-latest +
#   setup-python 3.10.12）同标签。--require-hashes 语义：任何包版本或字节与本清单不符即安装失败，
#   传递依赖悄然升级（如 attrs 发新版）不再能改变门禁运行条件。
#
# 诚实边界：本锁封闭的是 **pip 安装面**；ubuntu-latest 运行器镜像自身（OS 包、预装工具链）仍随
#   GitHub 滚动——那一层的钉死要自托管 runner 或容器镜像 digest 锁定，超出「测试依赖」范围，
#   未做就是未做（触发点：若未来证据要求 OS 级复现，另立一件事走裁决）。
#
