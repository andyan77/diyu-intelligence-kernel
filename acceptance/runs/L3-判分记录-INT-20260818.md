## 五条统一产品标准（Founder 原文逐字，2026-08-18，正式产品裁决）

1. 用户说"推广产品"或"制作产品内容"，默认进入正常内容制作，不要求用户先选择抽象商业目标。
2. 用户没有提出促销、清库存或折扣需求时，系统不得主动补出这些意图。
3. 信息已经足够执行时，系统应先交付完整结果；可选的经营信息放在结果之后提示，不应成为执行前的障碍。
4. 面对两个合理方向时，系统应先形成方案、解释各自侧重点和取舍，再请用户选择或优化；不能把未经整理的选择题直接退给用户。
5. 系统的价值是降低用户的思考和沟通成本，而不是把内部分类、目标判断和资料清单转交给用户完成。

**正式验收上的区别（Founder 原文逐字）**：前两个案例的旧考题本身要求系统追问目标或按库存激活处理，与本轮确认的产品标准发生冲突。因此它们的业务判定是"不通过"，但正式处理应是"旧考题口径需要修订后重跑"，不能把旧运行直接包装成已完成的最终验收失败。第三个案例可直接记为 L3 语义不通过。

### 案例二："为这件羊绒大衣制作春节前的视频号内容"

| 判分内容 | 您的判断 | 判分理由 |
|---|---|---|
| 用户的表达是否完整 | 完整 | 用户已经明确了商品、时间和发布平台：羊绒大衣、春节前、视频号内容。 |
| 系统是否应该主动关联促销 | 不应该 | 用户没有说打折、促销或清库存。系统不能因为"春节前"就主动推断用户有促销意图。 |
| 缺少促销边界是否应该阻止内容制作 | 不应该 | 没有促销信息，就按正常产品内容制作；春节只应作为内容主题或场景，不代表必须设计促销活动。 |
| 系统追加询问人设、账号、受众、材质证明、里料等信息是否合理 | 当前不合理 | 这些信息可以在确实影响内容时再补充，不能在用户已经表达清楚后一次性把大量问题退回给用户。 |
| 系统是否增加了用户认知负担 | 是 | 系统把清楚、可执行的内容制作任务，解释成缺少促销条件、暂时无法继续。 |
| 您认为系统应该怎样做 | — | 根据现有商品资料直接制作春节主题的视频号内容；没有促销信息就不写促销。必要时可以在输出后提示用户补充可选信息，而不是先阻止执行。 |
| 业务判定 | 不通过 | 系统主动脑补了用户没有表达的促销需求，并以此阻止正常内容制作。 |

### 案例三：同一件大衣，两个不同目标

| 判分内容 | 您的判断 | 判分理由 |
|---|---|---|
| 第一次"促进春节前库存消化"的处理 | 认可 | 用户明确提出库存消化目标，系统据此制定库存方向的方案，表现正常。 |
| 第二次"建立品牌长期价值"的处理 | 不认可 | 系统把"品牌故事还是品牌认知"的选择重新抛给用户，没有先完成自己的分析和方案设计。 |
| 系统是否识别出两个目标的差异 | 基本识别 | 系统知道库存消化和长期品牌价值不是同一件事，也没有把库存目标带入第二次任务。 |
| 系统是否完成了应承担的专业判断 | 没有完成 | 系统只识别出两个可能方向，却要求用户先替系统选择，增加了用户的决策负担。 |
| 您认为系统应该怎样做 | — | 综合已有商品和品牌信息，形成两个相对完整的最佳方案，分别说明侧重点、优缺点和适用结果，再询问用户更喜欢哪个方向、是否需要进一步优化。 |
| 两个目标是否应该产生不同方案 | 应该 | 库存消化应侧重短期销售与库存；长期品牌价值应侧重品牌故事、品牌认知或两者的组合。 |
| 业务判定 | 不通过 | 第一侧正常，但第二侧没有完成方案整理和专业建议，而是把基础判断工作重新交给用户。 |
